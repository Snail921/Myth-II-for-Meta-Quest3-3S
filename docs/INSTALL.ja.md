# 導入方法とPlugin Manager

[English](INSTALL.md) | **日本語** · [ホーム](../README.ja.md)

## 公開物について

現時点の公開物はManager・ソースと画像／スカイボックスです。**対応APKと一致する `runtime-seed.tar` が別途必要ですが、このリリースには含まれません。** 原作データの準備・変換はできますが、公開物だけで新しい端末への初回導入は完結しません。以下は開発版で確認した手順です。任意のランタイムを代用しないでください。[公開状況](RELEASE_STATUS.ja.md)も参照してください。

## 必要なもの

- Quest 3またはQuest 3S、開発者モードとUSBデバッグ、データ通信できるUSBケーブル。
- Windows PC、Python **3.11**（Tkinterを含む）、[7-Zip](https://www.7-zip.org/)、[Android SDK Platform Tools](https://developer.android.com/tools/releases/platform-tools)。これらは別途導入します。
- ご自身の対応するMyth II CD ISOとWindows用1.8.5アップデーター。ツールは必要ファイルを抽出し、アップデーター自体は実行しません。
- 原作セットアップ用にPCで最低 **8 GiB＋任意のHDアドオンのサイズ**。プラグイン変換・転送用の一時アーカイブには別途余裕が必要です。
- Questには原作データ、変換済みレベル、HDアドオン、ランタイム、転送時の一時領域が必要です。Managerは配置前に空き容量を検査します。初回展開にも空き容量が必要です。

ソース／ManagerのZIPを、書き込み可能なフォルダに構造を保って展開します。ZIP内から直接実行しないでください。そのフォルダで次を実行します。

```powershell
python -m pip install -r requirements-manager.txt
python -m tkinter
```

Tkinterの確認画面を閉じ、**Plugin Manager.cmd** を起動します。上部で **日本語／English** を選択できます。付属の `research/references/mythextract/scripts` は変換に必要なので削除しないでください。

## PCで原作を準備・変換する

1. 上部の「作業・保存先」に空き容量のあるフォルダを指定します。
2. 下部「原作セットアップ」で「ISOファイル」「1.8.5アップデーター」「7-Zip（7z.exe）」を指定します。
3. 任意で配布した「Skyboxes」フォルダを指定します。
4. 任意で「ロゴ画像」「CD画像」をそれぞれPNGファイルとして指定します。配布物の `Assets/Logo.png` と `Assets/CD_Face.png` を使えます。片方のみ・両方省略も可能です。出力時に名前を揃えるため、入力ファイル名は自由です。
5. 「任意のHDアドオンを追加」で、別途入手したアーカイブ本体を指定します。ダウンロードしたZIPのまま指定しないでください。Detail Texture Megapack・HD Megapackは同梱していません。分割されたアドオンは必要な部分をまとめて指定します。対応するADDON形式の検査を通る必要があります。
6. 「原作を展開・全レベルを変換」を押します。新しい `setup-…` フォルダが作られ、工程・件数が表示されます。`Game`、`LevelPacks/soulblighter`、`SharedAssets`、任意の `Skyboxes`、`setup-manifest.json` をまとめて保管してください。

対応EXEのSHA-256は `aa68153d987bf8a17c30bf8c7711d3b5e0a291a6cd1f8630446496715539181c` です。原作アーカイブは `tools/base-game-files.json` と照合します。別エディション・言語版等は拒否される場合があります。ファイル名だけ変更しても互換性は得られません。

## 新しいQuestへの初回導入（別途対応APK・ランタイムが必要）

1. Metaの開発者向け手順に従い開発者モードを有効にし、USB接続後にヘッドセット内の「USBデバッグを許可」を承認します。`adb devices` が `unauthorized` ではなく `device` になることを確認します。
2. 対応する外部データ版APKをサイドロードツール、または `adb install path/to/app.apk` で導入します。「提供元不明」から一度起動してフォルダ構成を作り、原作ゲームは起動しないでおきます。
3. Managerの「ADB」に `adb.exe` を指定し、「接続確認」で対象端末を選択します。
4. 「セットアップ結果」と「ランタイムデータ」を指定します。ランタイムのハッシュは `tools/runtime-seed.sha256` で固定しています。任意のWinlator環境の書き出しでは代用できません。
5. 「セットアップデータを配置」を押します。USB接続とヘッドセットの起動状態を保ちます。一時配置・ハッシュ検証後に有効化します。初回導入処理で既存の `Game` は上書きしません。
6. Questで **Initial setup / 初回データ展開** を選び、完了後 **Start Myth II / 原作を起動** を選びます。
7. 原作メニューからWillow Creekを開始します。VRに移行し、地形・ユニット・建物・情報パネル、選択・移動を確認します。

配置の再試行のために不用意にアンインストールしないでください。アプリ専用データも削除される場合があります。削除する場合は先にセーブ等をバックアップしてください。APK更新には署名の互換性が必要です。

## プラグインを追加する

上部の操作欄を使います。原作の初回導入が完了した環境が必要です。

1. 「原作フォルダ」にセットアップ結果の `Game` を指定します。`Myth II.exe`、`tags`、`plugins` があるフォルダです。
2. 「プラグインファイル」にゲームプレイ用アーカイブ本体を指定します。例：`Chimera Single-player`、`Magma - The Fallen Levels v2`。ZIPや親フォルダではありません。
3. 空き容量のある「作業・保存先」を指定し、**① レベルを検査**、内容確認後 **② 全レベルを変換** の順に進めます。
4. Questの原作ゲームを終了し、USB接続・端末選択を確認します。
5. 「変換済み bundle」が `catalog.tsv` と `source-files.json` を含むフォルダであることを確認し、**③ Questへ配置** を押します。原作プラグインとの組み合わせを照合し、転送後にハッシュを検証します。
6. 原作メニューでそのプラグインのレベルを選びます。対応するVRパックは自動選択されます。APK更新や初回展開のやり直しは不要です。

変換済みならbundleと対応する原作プラグインを指定して③のみ実行できます。**The Fallen LevelsではTFL GameplayをOFF**にしてください。複数ゲームプレイプラグインの組み合わせ、Unityモード、依存プラグインの自動解決は未対応です。スカイボックスだけを置いてもレベルは導入されません。このゲームプレイアーカイブ用フローでは、付属カットシーンなどの追加ファイルは自動配置しません。

## 高精細画像

初回セットアップで選択した対応HDアドオンは `Game/plugins` に配置します。APK外から画像を読み込むのでAPK更新は不要です。コミュニティ制作のアドオン自体は本リポジトリから配布しません。Quest起動画面の地形高精細・高解像度画像・詳細な影の設定を有効にし、設定変更後はレベルを読み直します。上部のゲームプレイ用プラグイン欄は汎用HDアドオンインストーラーではありません。

## 実機の配置先

`/sdcard/Android/data/org.mythvr.standalone/files/` の下：

```text
Game/                     原作EXE・tags・plugins・ユーザーデータ
LevelPacks/soulblighter/   原作キャンペーン変換結果
LevelPacks/plugin-…/      プラグインの変換結果
SharedAssets/             変換したUI、任意のLogo.png/CD_Face.png
Skyboxes/                 任意の「レベル表示名.png/jpg/jpeg」
runtime-seed.tar          一致する初回ランタイム
```

変換後のパックをファイル単位で改変しないでください。サイズ・SHA-256を検証します。更新はManagerでパック全体を配置します。旧版の隠しバックアップも容量を消費し、自動削除されません。

## トラブル時

- **未接続・unauthorized:** 開発者モード、USBデバッグ許可、ケーブル、`adb devices` を確認します。
- **原作が稼働中:** 原作を終了してから配置します。Managerはプレイを自動終了しません。
- **VRに移行しない:** EXE・原作プラグイン・パック・有効プラグイン順序の一致を確認し、診断ログをONにしてレベル名とエラーを報告してください。
- **転送が止まったように見える:** 経過時間は進捗の証拠ではありません。転送済みでも `adb push` が終了待ちになる開発版の既知事例があります。`作業・保存先/deployments/*.json` を確認し、配置済みパックを削除しないでください。Windowsのプロセス管理ツールで、このManagerの子プロセスである該当の `adb.exe push` を特定し、**その転送プロセスだけ**を終了します。Managerのエラー表示・後片付けを待ってから閉じるか再試行してください。全ADB/Pythonプロセスの一括終了や、有効化中のUSB切断は避けてください。この公開版に新しいキャンセル・タイムアウト修正を含むという意味ではありません。
- **容量不足・巨大パックの拒否:** PCの作業先を空き容量のあるドライブへ変更します。現在は1ファイル512 MiB・1レベル1 GiBの制限です。制限値を増やしても実行時メモリは増えません。

不具合報告には工程名・レベル／プラグイン名・エラー・必要なログを添えてください。原作アーカイブや個人の端末識別子は添付しないでください。
